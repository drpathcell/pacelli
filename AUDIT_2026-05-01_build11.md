## Issues found — actionable

### A1 · Storage backend picker is auto-skipped on signup (UX behaviour change)

Build 11 sends new email/password users straight from `Create Account` →
`Home` with no `Where should your data live?` picker. Pre-build-10, the
picker was the next screen. This is now silently defaulting to Cloud (Firebase).

**Severity:** Medium. Either intentional (good — fewer onboarding steps)
or a regression (bad — user can't pick On-Device any more).

**Action:** confirm with intent. If intentional, remove `StorageSetupScreen`
from the auth-success flow path and only show it on first launch from Settings
→ Storage. If unintentional, restore the redirect.

### A2 · System notification permission dialog appears BEFORE first sign-up

The `Pacelli Would Like to Send You Notifications` alert fires immediately on
launch, before the user has signed up or seen the home screen. iOS HIG advice:
defer permission requests until the user encounters the feature that needs it
(e.g. enabling task reminders). Asking up-front yields lower opt-in rates.

**Severity:** Low / UX polish. Not user-blocking but reduces opt-in.

**Action:** delay `requestNotificationPermissions()` until the user creates
their first task with a reminder, or until they explicitly tap a "Enable
notifications" toggle in Settings.

### A3 · The signup confirmation textfield occasionally retains the cursor placeholder

Audit screenshot showed the entered email reading `t.pacelli{epoch}@example.com`
instead of `audit.pacelli{epoch}@example.com` — the leading `audi` chars
were eaten somewhere between `clear()` and `send_keys()`. This is *probably*
a test-harness artefact (Appium clear/send-keys race on iOS), but worth a
look if real users ever paste an email and see characters disappear.

**Severity:** Probably harness only. Action: defer until reproduced manually.

## Test-harness limitations to address before next run

The audit script is shipped at `~/.claude/skills/pacelli-app-audit/`. These
items would lift coverage on the NEXT run:

1. **Bottom-nav tab tapping fails after Home renders.** The Appium
   `IOS_PREDICATE name == 'Tasks'` selector returns no match even though the
   accessibility tree clearly contains `XCUIElementTypeButton` with name
   "Tasks". Workaround: use `XCUIElementTypeButton[1]` etc. by index, or grab
   bottom-nav coordinates from the tree and tap by point.
2. **`Create Account` submit doesn't always land on Home in test conditions.**
   Add a longer wait (≥30 s) after notification-permission accept and before
   asserting Home, since Firebase Auth + Firestore round-trip on a slow sim
   takes 15-25 s.
3. **`webDriverAgentUrl` workaround required.** The xcuitest driver fails to
   spawn its own WDA on iOS 26.4 sims (`xcodebuild exited with code 70`). The
   skill bundles `start_wda.sh` + `wda_loop.sh` workaround scripts. Consider
   pinning xcuitest driver to a known-working version OR adding a clean
   `useNewWDA: true` retry path with `IPHONEOS_DEPLOYMENT_TARGET=18.0`.
4. **Email field intermittently retains stale chars.** Add a defensive
   `triple_click` + `select-all` + delete before `send_keys`.
