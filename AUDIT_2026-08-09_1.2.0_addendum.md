## Phase 1 — Crypto correctness

  `|| 0x01` counter byte. Vectors green in both directions.
- [PASS] Join codes reuse `deriveUserKey` / `encryptKeyForUser` unchanged. Key

- [PASS] `decryptNullable` still the only decrypt path for display; the E2E
  asserts no `[encrypted]` marker survives a code join.

## Phase 2 — Field encryption coverage
- [PASS] `household_join_codes.encrypted_key` is the household key wrapped for

- [PASS] Structural-only fields on the new doc: `household_id`, `created_by`,

- [PASS] `household_members.joined_via` is an identifier, not content — see the

## Phase 3 — Firestore rules

### Fixed (CRITICAL, was live)
- [FAIL→PASS] `household_invites` update was gated on `isMember()` inside the
  same batch that creates the membership. Rules never see a batch's own
  uncommitted writes, so every email-invite acceptance was denied and the client
  silently auto-provisioned a fresh household. Fixed with a narrow
  self-acceptance clause (addressed user, `pending -> accepted`, `status` the
  only mutable key, single-use). Locked by `invites.test.js`.

### Fixed (HIGH, was live)
- [FAIL→PASS] `household_members` create was a bare `allow create: if isAuth()`
  — any signed-in user could mint a membership **for anyone, in any household**,
  gaining read access to every encrypted document in it. Now self-only AND
  `joinAuthorised()`: the caller must name, in `joined_via`, the invite or join
  code that authorised them, and the rules re-read it server-side.
- [FAIL→PASS] `households` create did not bind `created_by` to the caller.
  Harmless before; now load-bearing, because `joinAuthorised()`'s founder branch
  trusts that field. Bound and tested.

### New surface — `household_join_codes`
- [PASS] The code is the document ID, never in the body. The security rests on
  three properties, all test-locked:
  1. `get` open to any signed-in user (that IS the flow), `list` member-only —
     so codes cannot be enumerated; guessing costs one read per attempt against
     ~39 bits (8 chars from a 30-char alphabet).
  2. Expiry enforced **server-side** (`resource.data.expires_at > request.time`),
     so a patched client gains nothing. `expires_at` is a real Timestamp,
     deliberately not the Dart ISO string used elsewhere — rules cannot compare
     ISO strings to `request.time`.
  3. Minting requires membership, self-attribution, and expiry inside 8 days
     (client asks 7).
- [PASS] Revocation is a delete by a member; regeneration deletes every older
  code, so rotation genuinely invalidates what was shared.
- [PASS] `household_id` denormalised; default deny at `/{document=**}` still
  last and still covers everything not explicitly matched.
- [NOTE — accepted] Anyone holding a live code can read the wrapped household
  key. That is the bearer model by design: the key is wrapped **for the code**,
  so holding the code already is holding the key. No additional exposure.
- [NOTE — accepted] `joined_via` persists a bearer reference on the member doc.
  Member docs are readable only by that user and their household co-members —
  exactly the people who can already `list` the code — and the value is dead
  once the code expires or is rotated. Reviewed and accepted over the
  alternative (no server-side proof of authorisation at all).

### Behaviour verified, not assumed
- [PASS] A `get` on a **non-existent** `household_members` doc is DENIED, not
  empty: `resource` is null and `resource.data.user_id` is an evaluation error.
  This cost a full E2E run. The client's "am I already a member?" pre-check is
  now a query; both the denial and the working query are pinned by tests in
  `join-authorisation.test.js` so nobody re-introduces it.
- [PASS] No composite indexes needed — every new query is equality-only, and
  `getCurrentHousehold` sorts client-side rather than adding an
  equality+orderBy index for a 1–2 document list.

## Phase 4 — Keychain, auth, guest mode
- [PASS] `SecureStore` unchanged: `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`.
- [PASS] `KeyManager.adoptHouseholdKey` writes the redeemed key to the same
  `hk_<householdId>` slot with the same accessibility; no new persistence path.
- [PASS] `discardOwnEmptyHouseholds` deletes the local key entry
  (`SecureStore.delete`) and the remote `household_keys` doc for the discarded
  household — no orphan key material left behind.
- [PASS] Welcome-screen join signs in anonymously only if there is no session,
  and `resetSession()`s on failure so a redemption attempt cannot strand a
  half-provisioned anonymous account (build 27 lesson upheld).
- [PASS] Guest upgrade path untouched; `linkWithCredential` still preserves uid,
  household and key.
- [PASS] No `print()` carries key material, a join code, or decrypted content.
  `[JoinCode] joined <householdId> via code` logs an identifier only.

## Phase 5 / 6
- [PASS] Entitlements unchanged (SIWA only). ATS unchanged. No new
  `Info.plist` exceptions.
- [PASS] Burn: its collection list and `HouseholdService.householdContentCollections`
  are now the same constant plus invites and join codes, so "what burn deletes"
  and "what makes a household empty" cannot drift — a household could otherwise
  be discarded while still holding data in a newly-added collection.

## Open, carried to 1.2.1
- **Builds 36 and 37 cannot join after this rules deploy.** They predate
  `joined_via`, so `joinAuthorised()` rejects them. Only build 38 is functional
  for joining. Both are TestFlight-only and superseded the same night; noted so
  nobody debugs it later.
- Empty-household discard is guarded (own household, sole member, no pending
  invite, zero docs in every content collection) but is still an irreversible
  delete driven by a client-side emptiness check. If it ever needs to be
  stricter, gate it behind an explicit user action.
- Face ID keychain gating still not implemented (carried from 1.0).
- Passphrase-encrypted export variant still open (carried from 1.1.0).

**Verdict: PASS.** Two live vulnerabilities closed (invite acceptance denial,
unrestricted membership creation) plus one latent one (`created_by` forgery).
Fix-order queue empty.
